# ربط نموذج طلب الصيانة بجوجل شيت (Google Apps Script)

اتبع الخطوات التالية بالترتيب لتفعيل استقبال طلبات النموذج في جوجل شيت.

## 1) إنشاء الشيت
1. افتح [Google Sheets](https://sheets.google.com) وأنشئ ملفًا جديدًا فارغًا.
2. في السطر الأول أضف رؤوس الأعمدة بالضبط كالتالي (خلية لكل عمود):

   ```
   Timestamp | Service | Name | Phone | City | Notes
   ```

## 2) فتح محرر Apps Script
1. من داخل الشيت: القائمة العلوية **Extensions** ← **Apps Script**.
2. سيُفتح محرر كود جديد باسم مشروع افتراضي (يمكنك تسميته مثلاً "نموذج طلب الصيانة").

## 3) لصق الكود
1. احذف أي كود موجود افتراضيًا في `Code.gs`.
2. الصق محتوى ملف `Code.gs` المرفق في هذا المجلد بالكامل.
3. احفظ المشروع (أيقونة الحفظ أو Ctrl/Cmd + S).

## 4) نشر المشروع كـ Web App
1. من أعلى يمين المحرر اضغط **Deploy** ← **New deployment**.
2. بجانب "Select type" اضغط أيقونة الترس واختر **Web app**.
3. اضبط الإعدادات التالية بالضبط:
   - **Execute as:** Me (حسابك)
   - **Who has access:** Anyone
4. اضغط **Deploy**.
5. قد يطلب منك جوجل تفويض صلاحيات (Authorize access) — وافق باستخدام نفس حساب جوجل مالك الشيت.
6. بعد النشر، ستظهر لك **Web app URL** — انسخ هذا الرابط بالكامل.

## 5) ربط الرابط بالموقع
1. افتح ملف `script.js` في مشروع الموقع.
2. ابحث عن السطر:

   ```js
   const SCRIPT_URL = "PASTE_YOUR_APPS_SCRIPT_URL_HERE";
   ```

3. استبدل النص `PASTE_YOUR_APPS_SCRIPT_URL_HERE` برابط الـ Web App الذي نسخته في الخطوة السابقة، مع الإبقاء على علامتي الاقتباس.

## 6) اختبار الإرسال
1. افتح الموقع، عبّئ نموذج "اطلب صيانة"، واضغط إرسال.
2. تحقق من ظهور صف جديد في الشيت يحتوي على البيانات المُرسلة.

## ملاحظة حول التعديلات المستقبلية
كل مرة تُعدّل فيها كود `Code.gs`، يجب إنشاء **نشر جديد** (New deployment) أو تحديث النشر
الحالي من **Manage deployments** حتى تنعكس التعديلات على الرابط المستخدم في الموقع.

## ملاحظة حول CORS
واجهات الويب التي ينشئها Apps Script لا تسمح للمتصفح بقراءة نص الاستجابة عند
الإرسال من نطاق (domain) مختلف باستخدام `fetch` العادي. لهذا السبب يرسل الموقع
الطلب بوضع `no-cors`، ما يعني أن البيانات تصل وتُحفظ في الشيت بنجاح، لكن الموقع
لا يستطيع قراءة رسالة النجاح/الفشل الفعلية القادمة من الخادم — لذلك تظهر رسالة
نجاح متفائلة ما دام الطلب قد أُرسل دون خطأ في الشبكة نفسها. إن احتجت لاحقًا لقراءة
استجابة حقيقية، يمكنك نشر بديل يُعيد ترويسة `Access-Control-Allow-Origin` بنفسه
عبر خدمة وسيطة (مثل Cloudflare Worker) أو استخدام أسلوب JSONP.
